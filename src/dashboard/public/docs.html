Technical reference

How the agent works

A continuous LinkedIn daemon — not cron jobs. One action at a time, human-like delays, warm outreach sequences, and a full SQLite audit trail.

Overview

The agent researches ICP-aligned people and posts via Unipile, engages (like / comment / view), sends connection invites only after a warm-up sequence, and publishes thought-leadership posts on Tue / Thu / Fri. Every mutating call goes through a rate limiter with daily quotas, burst pauses, and backoff.

No OS crons. Scheduling is an in-process loop that sleeps until the next opportunity. Working hours (Mon–Fri 08:00–19:00 local) gate all LinkedIn actions.

Daemon loop

On start: load env, write PID, reset burst counter, snapshot own profile. Then loop forever until halted or SIGTERM. 

flowchart TD
  Start([startDaemon]) --> Profile[fetchAndRecordProfile]
  Profile --> Loop{shutting down?}
  Loop -->|yes| Exit([exit])
  Loop -->|no| HB[writeHeartbeat]
  HB --> Halt{halted?}
  Halt -->|yes| Exit
  Halt -->|no| Pause{PAUSED?}
  Pause -->|yes| S60[sleep 60s]
  S60 --> Loop
  Pause -->|no| Hours{working hours?}
  Hours -->|no| SleepOff[sleep until next window]
  SleepOff --> Loop
  Hours -->|yes| Next[getNextScheduledAction]
  Next --> Idle{type = idle?}
  Idle -->|yes| S60
  Idle -->|no| Exec[executeAction]
  Exec --> Delay[human delay / burst via rate limiter]
  Delay --> Loop
  • Idle sleep — 60s when paused, no work, or quotas exhausted
  • Off-hours sleep — until next weekday morning (or 1h recheck on weekends)
  • Graceful stop — SIGTERM/SIGINT waits for the in-flight action, then clears PID
  • Halt — account restricted / disconnected stops the loop permanently until cleared

Schedule & windows

There are no cron expressions. Behavior is driven by calendar day, local hour, and quota state. The scheduler evaluates priorities in order:

  1. 1 Off hours → idle
  2. 2 Monday + quota → profile_audit
  3. 3 Tue / Thu / Fri + quota → create_post (beats engagement)
  4. 4 Weighted candidates for current time window (or post-boost weights)
  5. 5 No candidates → research if search allowed, else idle
  6. 6 8% browse pause (extra human delay) unless post-boost is active

Actions

Each action is a single LinkedIn verb. Mutating calls always run through executeWithRateLimit.

ActionBehaviorSequence effect

comment_post AI draft → humanize → safety → Unipile author → commented
like_comment Like first comment on a post none
view_profile Skip if viewed same id in 7 days; notify=true → viewed / maybe invite_ready
send_invite Only invite_ready targets; AI note → invited
create_post Trends → draft → publish; sets boost window —
research Search → ICP filter → score → upsert new discovered targets
profile_audit Monday AI suggestions (no auto-apply) —

ICP filter highlights

  • Exclude recruiters, coaches, spam title patterns
  • Exclude India / South Asia locations; prefer US, Europe, UK, Canada, AU, RU
  • People must match include title patterns
  • Posts: unless <6h old, need reactions + 2×comments ≥ 5
  • Keep discoveries with relevance score ≥ 75; engage preferred ≥ 80

Rate limits

First 14 days use ramp-up bases × 0.5. Afterward, steady caps apply. canAct checks: halt → pause → working hours → backoff → daily quota.
